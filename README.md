# 메뉴판

동네 가게 누구나 쓰는 **인쇄용 메뉴판**입니다. 주소를 열면 바로 쓰고, 설치할 것도 가입할 것도 없습니다.
고칠 때마다 브라우저에 자동 저장되어 다음에 같은 주소를 열면 이어집니다. [파일로 저장]을 누르면 메뉴판 전체가 파일 하나로 내려받아져, 그 파일만으로도 열립니다(백업 · 다른 컴퓨터로 옮기기).
메뉴판 사진을 올리면 AI(구글 제미나이)가 메뉴 이름 · 가격을 읽어 채워 줍니다.

- 열어 보기: https://menupan-jin.vercel.app/
- 만든 사람: 김광진 · kwangjin.owl@gmail.com

## 처음 열면

"메뉴판을 어떻게 시작할까요?"가 먼저 뜹니다. 새로 만드는 길 둘과, 이미 있는 메뉴판을 여는 길 둘이 있습니다.

- **빈 메뉴판으로 시작** — 상호명 · 메뉴판 맨 위(글자 또는 로고 이미지) · 추천 조합만 정하면 빈 메뉴판이 열리고, 바로 글자를 칠 수 있습니다.
- **사진으로 시작** — 지금 쓰는 메뉴판(손글씨도)을 찍어 올리면 AI 가 읽어 채웁니다. 읽은 메뉴는 사진 옆에 메뉴판 모양으로 놓여, 비교해 보며 고칩니다.
- **저장한 파일 불러오기** — [파일로 저장]으로 받아 둔 파일을 올려 이어서 씁니다.
- **알프스 예시 열기** — 이 파일이 출발한 가게(알프스)의 완성된 메뉴판을 열어 고쳐 씁니다.

한 번 고르고 저장하면 다음부터는 바로 자기 메뉴판이 뜹니다.

## 무엇을 누르나

아래에 버튼 넷이 있습니다.

| 누르는 것 | 하는 일 |
|:--|:--|
| **편집** | 글자를 눌러 고칩니다. 이름 · 가격 · 설명을 바꾸고, 메뉴를 넣고 빼고 순서를 옮깁니다. 켜면 오른쪽에 **꾸미기** 창이 함께 열려 글꼴 · 색 · 단 수 · 그림을 고릅니다 |
| **파일로 저장** | 지금 모습 그대로 파일 하나가 내려받아집니다(`상호명-메뉴-날짜.html`). 백업하거나 다른 컴퓨터로 옮길 때 씁니다 — 평소에는 자동 저장됩니다 |
| **인쇄** | 인쇄 창이 열립니다. 화면에서 보던 모습 그대로 A4에 나옵니다 |
| **?** | 쓰는 방법 안내 |

편집 중에는 위에 **미리보기**가 생깁니다. 고치는 표시를 모두 걷고 인쇄될 모습만 보여 줍니다.
안 들어가는 것이 있으면 종이 아래에 붉은 띠가 서서 어느 단이 무엇에 얼마나 겹치는지 알려 주고, 글자를 몇 %로 낮추면 들어가는지도 알려 줍니다.

## 왜 이런 모양인가

**쓰는 사람이 컴퓨터에 익숙하지 않은 가게 주인**입니다. 이 제약이 모든 결정의 기준이었습니다.

- **계정이 없습니다.** 로그인을 만들면 사장님이 아이디와 비밀번호를 관리해야 하고, 개인정보도 받게 됩니다. 사진 읽기에 쓰는 AI 키는 서버(버셀)에만 두어 사장님은 키가 필요 없습니다
- **처음 보이는 버튼이 넷뿐입니다.** 고치는 일은 전부 편집 안에 넣었습니다
- **화면과 인쇄가 같습니다.** 프린터가 못 찍는 가장자리를 화면에서도 흰 테두리로 비워 두고, 그것을 뺀 나머지로 여백을 잡습니다
- **크기는 사장님이 정합니다.** 안 들어가면 저절로 줄이지 않고 알려만 줍니다. 저절로 줄이는 기능을 네 번 만들었다가 네 번 다 걷어냈습니다

메뉴 장과 와인 장이 있고, 와인은 병 모양 아홉 가지와 색을 골라 카드로 보여 줍니다.
반대로 **하지 않기로 한 것**도 있습니다. 예약, 지도, 챗봇, 관리자 모드를 검토하고 넣지 않았습니다. 더 나은 서비스가 이미 있는데 억지로 넣으면 더 불편해지기 때문입니다.

## 어떻게 만들었나

친구가 운영하는 가게 **알프스**의 손글씨 메뉴판 사진 한 장에서 출발했습니다. 친구가 쓰면서 한 말로 기능을 만들었고, 그다음 다른 가게도 쓰도록 빈 메뉴판과 첫 화면을 더했습니다. 알프스 메뉴판은 지금 파일 안에 예시로 들어 있습니다.

코드를 직접 쓰지 않고 AI와 대화로 만들었습니다. 대화가 여러 번 끊겨, 결정마다 번호를 붙인 **결정 기록**과 인수인계 문서를 남겨 다음 대화에 넘기는 방식으로 이어 갔습니다. 코드 주석에도 그 번호가 붙어 있습니다.

AI가 "넣었습니다"라고 답해도 실제로는 안 들어간 일이 반복돼, 말을 믿는 대신 파일을 직접 열어 확인하는 **자동 검사**를 만들었습니다. 화면 없는 크롬으로 메뉴판을 열어 인쇄 여백을 mm로 재고, 저장했다 다시 연 파일이 그대로인지 보고, 버튼을 실제로 눌러 보고, 편집 화면과 완성본의 위치 차이가 0px인지 봅니다. 고치기 전 파일과 후 파일에 똑같이 돌려, 달라진 것이 이번에 고친 것뿐인지 확인합니다.

## 파일

| | |
|---|---|
| `index.html` | 메뉴판 전부. 이미지 · 데이터 · 기능이 한 파일에 들어 있습니다. 열면 첫 화면이 뜹니다 |
| `api/read.js` | 버셀 서버 함수 — 메뉴판 사진을 제미나이로 읽습니다. **AI 키는 여기서만 씁니다** |
| `tests/alps_check.py` | 자동 검사 |

글꼴은 파일에 들어 있지 않고 [구글 폰트](https://fonts.google.com)에서 받아 씁니다.

## 구조

화면(`index.html`)은 버셀에서 서빙합니다. 사진 읽기는 버셀 서버 함수(`api/read.js`)가 제미나이를 부르고, **AI 키는 서버에만** 둡니다 — 쓰는 사람은 키가 필요 없습니다.
